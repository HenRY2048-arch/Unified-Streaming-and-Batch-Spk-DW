# Mock Generator 生成侧改造点清单

> 目的：作为"业务换血"的**执行依据**，**只针对生成器**（`/RealTime`），**不动 T 层**。
> 顺序铁律：**改生成器 → 冻结事件契约 → 改 T 层**；契约冻结前不碰数仓代码。
> 粒度：本清单只列**改造点**；字段级 schema、比例/规模参数一律标注「待定」。
> 日期：2026-10-16

---

## 0. 现状定位

- **正本**：`/RealTime`（Maven / JDK 8 工程，9 个 Java 类 + 1 个 Scala 消费端）。
- `RealTimeConsumer.scala` 是**冒烟测试**，不属于管线；其 **11 字段 Schema 即当前事件契约**。
- `/RealTime` 内的文档与仓库旧文档**同源重复**：以仓库侧的处置为准，`/RealTime` 内副本按弃用处理。
- **待重造的心脏**：`MockGenerator.generateNextEvents()` —— 现为"按权重抽一个独立事件"。

---

## 1. 一句话目标

把生成器从 **"独立事件抽样"** 改造成 **"会话旅途 + 分发循环 + 有限有向图"**：
让 曝光 → 点击 → 消费 → 互动/关注 形成**因果链**，让社交图成为**旅途的下游产物**，
并让生成器**记录归因真值**。

## 4. 验收标准

1. 能产出**带曝光的会话旅途**，且"曝光 → 点击 → 消费 → 互动/关注"能**对得上**（因果链成立）。
2. 能产出**有限有向图**，且其增长**由旅途驱动**（不是独立演化）。
3. **归因真值可校验**：生成器记录的真实来源路径，可与数仓归因结果对账。
4. **体量可控**：投喂长度与会话频率是**旋钮**，单机跑得动。
5. **压力可测**：可在**不同负载档位**与**不同分发策略**下稳定运行，且策略/档位均由**配置**切换。

## 6. 红线

- **只改生成器，不动 T 层**；契约冻结前不碰数仓代码。

- 事件是**因果链**，不是独立抽样。
