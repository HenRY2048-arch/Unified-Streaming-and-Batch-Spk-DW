## 0. 业务目标（本文的一切判断以此为准）

1. 微博式内容社区，**主角是"内容分发"**（不是关系沉淀）。
2. 闭环：作者供内容 → 关注流/推荐/探索（比例动态）分发 → 消费 → 反馈 → 回流分发与供给。
3. 分析目的是**归因**（关系怎么长出来、内容怎么转化）；方法＝统一证据层 + 分治口径层。
4. 消费者：创作者中心（主看板）、**data agent**（改造后加）、推荐系统（**仅概念**）。
5. 架构：**批流一体**（批为真值、流为近似，同一存储 + 同一逻辑）。
6. 独有优势：模拟器有 **ground truth**，归因可校验。

## 1. 四条设计原则

1. **曝光为根**：一切漏斗/比率的分母是**曝光**，不是点击。
2. **批流分级**：流只留"真需秒级"的；其余一律回批（单机 7.58GB，克制是硬约束）。
3. **三层交付**：**证据层**（DWD 明细）+ **口径层**（DWS 指标）+ **语义层**（指标字典）——托底看板 / agent / 推荐。
4. **真值对账**：归因类与热度类指标，都能与真值对账。

### 1.1 "非废指标"判据（每个指标至少满足其一）

- **(a) 有下游**：看板 / agent / 推荐（概念）；
- **(b) 服务数仓自身**：可重跑、口径校验、与真值对账；
- **(c) 服务长期离线分析**：分布 / 对比 / 生命周期等探索性分析。

> 三者都不沾 → 废指标，删除。

## 2. 边界：数仓算什么，不算什么（**重要**）

| 属于数仓（客观、可复现、可对账） | 属于应用层（个性化、决策） |
|---|---|
| 曝光 / 点击 / 消费 / 互动的**事实与聚合** | 用户–内容**匹配度** |
| **内容热度**（内容侧、与用户无关） | **排序分数**的生成 |
| 渠道 / 位置 / 作者的**分布与效率** | **分发决议**（派什么、比例多少） |
| 归因**证据与口径**（last-touch 等） | 归因结果如何**用于决策** |

- 数仓**可以分析** `rank_score`（位置偏差、排序质量），**不生产**它。
- **热度 ≠ 个性化**：热度只由事件聚合而来；"给谁看"是应用层的事。

## 4. 关键口径（示例，其余 P3 细化）

### 4.1 F-07 内容热度

```
heat(item, t) = Σ w_e × count_e + 0.02 × Σ min(dwell_sec, 30)
                e ∈ {曝光, 点击, 赞, 藏, 评, 转}
                窗口 = (anchor − minutes, anchor]，minutes ∈ {60, 1440}
```

- **性质**：内容侧、**与用户无关**；可复现、可重算。
- **窗口**：滚动窗口（默认 1h 与 24h 两档）；**窗口本身即衰减**，不做额外指数衰减。
- **粒度**：item；可上卷 author / category / channel。
- **双实现**：**流侧近似**（微批增量，秒–分级）＝"实时热度"；**批侧全量重算**＝"真值热度"。
- **对账**：`V-02` 比较两者（这是批流一体的验证点，见 §4.5）。
- **权重 `w_e`**：**已冻结为 `heat-v1`**：曝光 `0.1` / 点击 `1` / 赞 `3` / 藏 `4` / 评 `6` / 转 `8`；
  停留 `0.02 × 秒`、单段上限 `30` 秒。全部走配置，后续 agent 可在区间内调参，不阻塞 P3.8。
- **停留与曝光**：**停留分不要求该窗口内有曝光**；因此可能出现“曝光 0、仅凭停留上榜”。
  这是显式口径选择，字典必须标注该限制（长驻留注入会放大）。

### 4.2 F-04 CTR

`CTR = 点击量 / 曝光量`，按 **渠道 × 位置 × 内容 × 作者 × 时间** 下钻。
**分母必须是曝光**（旧实现用 `enter_item` 当分母，语义错误）。

### 4.3 C-03 负反馈率

`负反馈率 = (dislike 数 + 秒退数) / 曝光量`；**秒退 = 0.2–1.2 秒**。
（旧 U-10/U-12 的"跳出率"并入此项，且分母由 click 改为曝光。）
“不到 0.8 秒且长内容”的超速**不重复计入 C-03**，它是 Q-02 的诊断量；否则与秒退重叠、会重复计数。
> 运行校准（2026-10-20）：D1 的 0.2–1.2s 与 E1 的 <0.8s 在事件层重叠，
> 可观测的秒退总量约 **20%**、短停留总量约 **14%**；15%/5% 是生成器注入参数，不能分别观测。

### 4.4 R-03 关注转化途径（last-touch）

对每条 `follow`：取其 `source_item_id` / `source_user_id` / `channel`，归到"**从哪条内容、哪个渠道、在会话的哪一步**产生了关注"。
输出：**来源构成**（按渠道/内容/作者）× **转化率**。可与 `V-01` 对账。

### 4.5 V-01 / V-02 自我验证

- `V-01`：数仓重建的关注/互动归因 vs `content_groundtruth` 的**命中率**（last-touch 是否等于真值来源）。
- `V-02`：流侧热度 vs 批侧热度真值的**偏差**。
- 二者是"**批为真值、流为近似**"落到可度量的形式，也是本项目相对现实数仓的唯一增量价值。

## 5. 语义层与维度一致性（托底 agent / 看板）

**一致性维度**（所有指标共享）：`时间`（日期/小时）、`user`、`item`、`author`、`category/tags`、`channel`、`session`。

**指标字典（必备交付）**：每个指标声明

```
编号 ｜ 名称 ｜ 口径（分子/分母） ｜ 粒度 ｜ 可下钻维度 ｜ 时效(Tier) ｜ 证据来源字段 ｜ 是否可重算 ｜ 真值来源
```

> 给 agent 托底的**核心不是指标数量，而是这份字典 + 颗粒度稳定**——否则 agent 无法可靠地选表、算对分母、正确下钻。
>
> P3.9 起，落表字典额外提供 `query_table`、`query_mode`、`read_only`、`contract_version`：
> agent 不需要从说明性文字猜测应该读 DWS、DWD、Redis 还是现算。

## 8. 已定与待定

**已定（2026-10-16；v1.2/v1.3 补充）**

1. **时间粒度**：Tier 1 用**小时**、Tier 2 用**天**；
2. **负反馈构成**：`dislike + 秒退(0.2–1.2s)`；超速（<0.8s 且长内容）只作 Q-02 诊断，**不重复计入 C-03**；
3. ~~`★★★` 三项**首版之后**~~ → **改为与其它指标同步实施**（2026-10-16 决定）；代价：需生成器先引入**模拟时钟**，否则 24h / 次留 / N 天窗口在本地跑不出来；
4. **指标字典形态**：**DWS 宽表 + 指标字典（MD）+ 一张元数据表**（元数据表是给 agent 的兜底）；**字典新增"性质"列**（业务 / 风控 / 验收 / 自检），避免 agent 把自检类指标当业务量解释；
5. **新用户口径**：`U-02` 出**双口径**——**注册口径（主）**＝`user_registered` 事件按 `user_id` 去重；**观测口径（自检）**＝`dim_user.first_seen_dt`；两口径差值＝埋点缺口/迟到，持续监控；
6. **停留时长口径**：以事件字段 `leave_item.duration_sec`（模型真值）为准；`leave_ts − enter_ts` 仅作**交叉校验**（模拟时钟启用后二者应收敛）；
7. **负反馈口径**：主口径**保留混合**（含 D1 注入），不新增"纯涌现"编号；注入基线由 `Q-02` 提供对照，字典标注"含注入噪声"；
8. **热度停留**：停留分**不要求曝光**；`heat-v1` 权重冻结为曝光 `0.1` / 点击 `1` / 赞 `3` / 藏 `4` / 评 `6` / 转 `8`，
   停留 `0.02×秒、单段上限 30`，不做额外指数衰减；
9. **留存 cohort**：注册用户用**注册日**、种子用户用**首见日**，增加 `cohort_type(seed/registered)`；
   U-03 主口径只看 registered；档位 **1/3/7**，14 天待数据跨度足够再加；
10. **字典结构**：`semantic/metric_dict` 增加 `limitations` 列（推断量/注入噪声/右截断/自检性质）。

**待定**

无 blocking 项。仅保留长期调参（agent 在区间内调整阈值）与 14 天留存扩展。

## 9. 互动计数口径与数据源缺口（历史缺口，已修）

**代码事实**：

- 旧脚本：反馈 `{like, fav, share, dislike}` **四选一**（事件级互斥）；
- 新脚本（修复前）：五类互动独立触发 → 一次消费可能同时 `like` + `dislike`；且互动无状态（可跨会话重复点赞同一内容）；
- 对照：`follow/unfollow` **有状态**（`isFollowing` + 改图），二者**不对称**。
- **✅ 已修（2026-10-16，源头：生成器）**：见下表层次一/二。

**三个层次**

| 层次 | 内容 | 是否碰契约 | 状态 |
|---|---|---|---|
| 一 | 同一次消费内**互斥**（先定态度，再定其它反馈） | 不碰 | ✅ **已修**（P1.3 补丁） |
| 二 | 跨会话**去重**（per-(user,item) 态度状态，与 `follow` 对称） | 不碰 | ✅ **已修**（`InteractionState`） |
| 三 | **撤回**（`unlike` / `unfav`） | **碰契约** | ⛔ **首版不做**，列为可选扩展 |

**实测不变量（修复后，15 秒样本）**：`like` 46 事件 / 46 去重 / **0 重复**；`like ∩ dislike = 0`；`fav` **0 重复**；`comment`/`share` 仍可重复。

### 9.1 定稿：like / dislike 语义（**模型假设，已确认**）

对每个 `(user, item)`：

```
stance ∈ { NONE, LIKE, DISLIKE }    一次定，互斥，不可逆（吸收态）
· 仅在"首次消费该内容且 stance = NONE"时判定一次（单次掷骰分区间 → 保证互斥）
· 一旦定下：不再产生 like/dislike；不能取消、不能改成对方
· stance = DISLIKE 时禁止 fav；LIKE / NONE 时 fav 可（fav 自身也是一次性状态）
· 动作型行为不受限：comment / share / 再次消费 / click_tag / enter_profile / follow 照常
```

**由此得到的口径（写进指标字典）**

- **累记点赞数（截至 T）** ＝ `count(like 事件)` ＝ **distinct 点赞用户数**，**单调不减**；
- **窗口新增点赞数** ＝ 窗口内 `like` 事件数，**不重叠窗口可加和**；
- **用户正/负反馈** ＝ 其 `stance`（唯一、终身不变）；
- `I-01 互动量` **同时提供两种口径**：**互动事件数**（flow）与**互动去重数 / 关系数**（state）；
  字典须写明**分子定义 + 去重键**（`item_id` / `author_id`）。

**已知代价（显式接受）**：累计赞数不会因"后悔"下降；"态度随时间变化"类分析**不做**。
若将来要支持，需新增 `unlike`/`unfav` 事件（**契约变更**：`schema_version` 升级），且数仓改为**净额/状态**计算。
